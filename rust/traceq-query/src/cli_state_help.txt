traceq stat FILE [--json]
    Reports the trace profile, register layout, event totals and gaps after full input validation.

traceq instructions FILE [--from E --to E] [--mnemonic NAME ...] [--gaps] [--gap-reasons] [--gap-reason REASON ...] [--limit N --offset N] [--json [--location]]
    Repeat --mnemonic to select any exact recorded mnemonic before pagination.
    It combines with event and gap filters. The full trace is still validated.
    --gap-reasons adds the positioned gap_count and distinct gap_reasons for each instruction.
    --gap-reason matches any selected reason before pagination and includes all reasons for each match.
    Accepted reasons are unsupported, unconfirmed_store, foreign_thread, exclusive_region,
    outside_data_range, outside_code_range.
    --location --json adds the unique recorded module name, base and offset.
    PCs with no unique recorded module keep null module fields.
    Unpositioned loss is reported in capture metadata.

traceq boundaries FILE [--from E --to E] [--target-module NAME] [--reg x0]... [--limit N --offset N] [--json]
    --target-module selects exits by the exact recorded target module name.
    Pagination counts the matches. Capture totals and reentry evidence still apply.

traceq find-pc FILE (--off O | --addr A)... [--limit N] [--json]
traceq find-pc FILE --module NAME --off O [--off O ...] [--limit N] [--json]
    --module selects one exact recorded module name. off stays capture-relative.
    Module queries also return module_offset and meta.module_base. Without --module,
    --off selects an offset from meta.code_base.
    --location --json adds each hit's recorded module name, base and offset.
    A PC with zero or multiple containing modules has null module fields unless
    --module selects an exact recorded instance. off stays capture-relative.

traceq reg-state FILE --at-ev E [--phase pre|post] [--reg x0]... [--json]
    Pre is the default phase. Without --reg, shows x0 through x7 and nzcv.

traceq mem-access FILE --range BASE,LEN [--range BASE,LEN ...] [--pc PC ...] [--read|--write] [--from E --to E] [--limit N --offset N] [--compact] [--json [--location]]
    Up to 64 ranges share one validated scan. Each matching recorded access is
    returned whole and once, in trace order. Filters and pagination apply to the union.
    Repeat --pc up to 64 times to select exact recorded instruction addresses.
    PC selection combines with ranges, direction and event windows before pagination.
    --compact --json uses columns-v1 arrays, with columns and rw-indexed value_sources in meta.
    Rows retain ev/pc/off/rw/addr/size/known/val; unknown values stay null.
    Each page is self-contained; limits still count actual accesses and validate the full stream.
    --access-index --json adds the zero-based index within the instruction before filtering.
    With --compact it selects columns-v2, with access_index appended to each row.
    --source-table --compact --json selects columns-v3, including for mixed sources.
    Each row ends in value_source_ref, a zero-based index into meta.value_source_table.
    The table is page-local. An empty page has an empty table. --access-index is optional.
    --location --json adds meta.pc_locations, keyed by each PC shown on the page.
    Each entry gives the unique recorded module, base and offset, or null module fields.
    Row off remains relative to the capture code base.
    Each range length is 1..4096 bytes. For example, --range 0x1000,16 selects 16 bytes.
    Mixed ordinary and atomic write sources keep named rows with
    meta.compact_fallback=mixed_write_sources unless --source-table is selected.
    Atomic add writes use recorded old bits and the addend. Halfword CAS and SWP
    use returned old bits and saved inputs. Failed CAS leaves an unconfirmed-store gap.
    Whether a failed CAS wrote back the old value remains unknown.

traceq mem-state FILE --range BASE,LEN --at-ev E [--phase pre|post] [--compact] [--json]
traceq mem-state FILE --range BASE,LEN --checkpoint E:pre --checkpoint E2:post [--json]
    Profile2 checkpoints share one validated scan; 1..64 requests, input order retained.
    --limit/--offset page bytes independently per checkpoint; whole page <=4096 byte cells.
    meta.total/shown count byte cells; meta.next advances all checkpoints together.
    Optional --compact --json uses mem_state_format=hex-v1 for single/batch snapshots.
    Each frame has address, size, data_hex and one sources entry per byte:
      null means unknown (00 is a placeholder); [observed_ev,pc_index] means known.
    meta.pc_table preserves each source PC and pc_offset; references are page-local.
    --access-source --json adds observed_rw (r/w) and observed_access_index to known bytes.
    The index is zero-based within that instruction's recorded memory accesses.
    With --compact this selects hex-v2: [observed_ev,pc_index,observed_rw,observed_access_index].
    --source-runs --compact --json selects hex-runs-v1. Its source_runs contain
    [byte_count, source] pairs in byte order. A source uses meta.source_columns
    or null for unknown bytes. Each run covers adjacent bytes with that source.
    Sources describe the last observation at the checkpoint, which may be a read.
    Counts/limits still measure bytes, including unknowns; empty frames have size 0.
    All input validation, gap/completion semantics and checkpoint fields are retained.
    With --json, repeat --range for up to 64 ranges sharing one validated scan.
    ranges-checkpoints-v1 returns one group per range, in request order, with
    range_base, range_size and the checkpoints in data. The byte offset and
    limit apply to each range. The 4096-cell cap covers all ranges and checkpoints.
    To give ranges different checkpoints, place --range-checkpoint E:pre or E:post
    after its --range. Each range needs at least one, with up to 64 in total.
    This mode uses meta.checkpoint_pairs and cannot mix with --checkpoint or --at-ev/--at-seq/--phase.
    Each range length is 1..4096 bytes. For example, --range 0x1000,16 selects 16 bytes.
